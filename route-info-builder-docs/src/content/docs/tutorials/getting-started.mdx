import { Steps, Tabs, TabItem, FileTree, Aside, LinkCard } from '@astrojs/starlight/components';

This tutorial takes you from an empty Rust project to generated routing artifacts and two working calls: one through the Rust `Link` enum, one through a TanStack Query hook in React. It uses the build-script integration, which regenerates the artifacts every time you compile.

**Prerequisites**

- Rust 1.88 or newer (the crate's MSRV).
- Node.js 22+ and pnpm 10 for the frontend half of this tutorial.
- No prior route-info-builder knowledge. The environment starts clean.

<Steps>

1. **Create the Axum project and one controller file.**

    ```bash
    cargo new shop-api
    cd shop-api
    mkdir -p src/controllers
    ```

    Add the runtime dependencies to `Cargo.toml`:

    ```toml
    [dependencies]
    axum = "0.8"
    tokio = { version = "1", features = ["full"] }

    [build-dependencies]
    route-info-builder = "0.2"
    ```

    Create the controller `src/controllers/users.rs`. The scanner looks for a function named `routes` inside every `*.rs` file under your controllers folder:

    ```rust
    use axum::routing::{get, post};
    use axum::Router;

    pub fn routes() -> Router {
    Router::new()
      .route("/api/users", get(list_users))
      .route("/api/users", post(create_user))
      .route("/api/users/{user_id}", get(get_user))
    }

    async fn list_users() -> &'static str {
    "[]"
    }

    async fn create_user() -> &'static str {
    "created"
    }

    async fn get_user() -> &'static str {
    "user"
    }
    ```

    Your project now looks like this:

    <FileTree>
    - shop-api
        - src
            - controllers
                - users.rs
            - main.rs
        - Cargo.toml
    </FileTree>

2. **Write the build script.**

    Create `build.rs` in the project root. Every field below is a real configuration key; `Config` implements `Default`, so you only set what you need:

    ```rust
    use route_info_builder::{Config, RustConfig, TypeScriptConfig};

    fn main() {
    let config = Config {
      controllers_path: "src/controllers".into(),
      rust: RustConfig {
        output_file: Some("src/links.rs".into()),
        ..RustConfig::default()
      },
      typescript: TypeScriptConfig {
        generate_client: Some(true),
        output_path: Some("../web/src/api".into()),
        ..TypeScriptConfig::default()
      },
      ..Config::default()
    };

    route_info_builder::generate_links(&config).expect("failed to generate route links");
    }
    ```

    This one call scans once, returns the generated Rust code, and writes every configured output to disk, creating parent directories as needed.

3. **Generate the artifacts.**

    ```bash
    cargo build
    ```

    You should now see the generated files, and Cargo prints the scanner's build-time note about the TypeScript client:

    ```ansi
    ​warning: route-info-builder: generated TypeScript client at ../web/src/api
    ```

    Your tree now contains three generated files:

    <FileTree>
    - shop-api
        - src
            - controllers
                - users.rs
            - links.rs
            - main.rs
        - build.rs
        - Cargo.toml
    </FileTree>

    Open `src/links.rs`. You should see one enum with one variant per route — the method is part of the name by default, and path parameters become fields:

    ```rust
    pub enum Link {
    GetApiUsers,
    PostApiUsers,
    GetApiUsersUserId { user_id: String },
    }
    ```

    Open `../web/src/api` (it does not exist yet, the build script creates it): you should find `client.ts`, a self-contained HTTP client with typed methods, and `api.ts`, the TanStack Query hooks.

4. **Use the `Link` enum in Rust.**

    Declare the generated module in `src/main.rs` and try the three methods every variant carries:

    ```rust
    mod links;

    use links::Link;

    #[tokio::main]
    async fn main() {
    let user_link = Link::GetApiUsersUserId { user_id: "123".to_string() };

    println!("Path: {}", user_link.to_path()); // /api/users/123
    println!("Method: {}", user_link.method()); // GET
    println!("Name: {}", user_link.name()); // getApiUsersUserId
    }
    ```

    Run it:

    ```bash
    cargo run
    ```

    ```ansi
    Path: /api/users/123
    Method: GET
    Name: getApiUsersUserId
    ```

    `name()` returns the same key the TypeScript client uses, which keeps query keys in sync across both languages.

5. **Create the frontend and install TanStack Query.**

    In a second terminal, still inside `shop-api`, scaffold a React app into `web/`:

    <Tabs>
    <TabItem label="pnpm">
      ```bash
      pnpm create vite@latest web --template react-ts
      cd web
      pnpm install
      pnpm add @tanstack/react-query
      ```
    </TabItem>
    <TabItem label="npm">
      ```bash
      npm create vite@latest web -- --template react-ts
      cd web
      npm install
      npm install @tanstack/react-query
      ```
    </TabItem>
    <TabItem label="yarn">
      ```bash
      yarn create vite@latest web --template react-ts
      cd web
      yarn install
      yarn add @tanstack/react-query
      ```
    </TabItem>
    </Tabs>

6. **Call the API with the generated hooks.**

    The generated `api.ts` exposes one hook per route: `useQuery` hooks for GET routes and `useMutation` hooks for everything else. Replace the contents of `web/src/main.tsx`:

    ```tsx
    import { StrictMode } from "react";
    import { createRoot } from "react-dom/client";
    import { QueryClient, QueryClientProvider } from "@tanstack/react-query";
    import App from "./App";
    import "./index.css";

    const queryClient = new QueryClient();

    createRoot(document.getElementById("root")!).render(
    <StrictMode>
      <QueryClientProvider client={queryClient}>
        <App />
      </QueryClientProvider>
    </StrictMode>,
    );
    ```

    Replace `web/src/App.tsx`:

    ```tsx
    import { useGetApiUsers, useGetApiUsersUserId } from "./api/api";

    export default function App() {
    const { data: users, isLoading } = useGetApiUsers();
    const { data: user } = useGetApiUsersUserId({ userId: "1" });

    if (isLoading) return <p>Loading...</p>;

    return (
      <main>
        <h1>Users</h1>
        <pre>{JSON.stringify(users)}</pre>
        <pre>{JSON.stringify(user)}</pre>
      </main>
    );
    }
    ```

    The second hook takes a typed parameter object — the generator emitted a `GetApiUsersUserIdParams` interface with a `userId: string` field from the `{user_id}` path segment.

    Build the frontend to confirm everything type-checks:

    ```bash
    pnpm build
    ```

    You should see Vite finish without type errors. The generated hooks compile inside your app with no additional wiring: the client module is self-contained and handles headers, JSON parsing, 204 responses and error transformation itself.

    <Aside type="note">
    The hooks show `any` return types here because the stub handlers return plain strings. The scanner also reads handler bodies: `format::json(...)` conversions, `Query<T>` extractors, `Json<T>`-style bodies and returned error variants all become TypeScript types. See [How scanning works](/explanation/scanning-pipeline/).
    </Aside>

7. **Regenerate after changing routes.**

    Add a route to `users.rs`, or a new controller file, then run `cargo build` again. The scan is deterministic — files are visited in sorted order — so the output only changes when your routes change.

</Steps>

<Aside type="tip">
  If `cargo build` reports that no routes were found, check that your files are not named `mod.rs`, that the function is named `routes`, and that routes built in local variables are registered through statement chains. The [troubleshooting guide](/guides/troubleshoot-scanning/) covers every known failure mode.
</Aside>
