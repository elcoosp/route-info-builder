This guide shows you how to control the names the generator produces: which method appears in them, which path prefix disappears from them, how they are cased, and what happens when two routes would produce the same variant name. URL paths are never affected — every naming key changes names only.

**Preconditions**

- A working `route-info.toml` (or an in-code `Config`) with `controllers_path` set.
- The names you want to change are visible in a generated `links.rs` or `client.ts`.

## Shorten names by removing a path prefix

<Code lang="toml" code={`[naming]
path_prefix_to_remove = "/api"`} />

`GET /api/users` then produces the variant `GetUsers` while `to_path()` still returns `/api/users`. Prefix matching is segment-aware: removing `/user` does not touch a `/users` route.

## Drop the HTTP method from names

By default the method is part of every base name, which is why `GET /api/users` and `POST /api/users` become `GetApiUsers` and `PostApiUsers`. Remove it when your routes do not collide without it:

<Code lang="toml" code={`[naming]
include_method_in_names = false`} />

With collisions likely (one path, several verbs), prefer a [collision strategy]() over dropping the method.

## Change the casing

<Code lang="toml" code={`[naming]
variant_case = "pascal" # enum variants, default
field_case   = "snake"  # parameter fields, default`} />

Accepted spellings for both keys: `camel`/`camelCase`, `pascal`/`PascalCase`, `snake`/`snake_case`, `kebab`/`kebab-case`, `title`/`Title Case`, `lower`/`lowercase`, `upper`/`uppercase`. An unknown spelling falls back to the default for that key.

`GET /api/users/{user_id}` with `field_case = "camel"` produces the field `userId` instead of `user_id` — the same spelling the TypeScript parameters interface uses.

## Keep digits glued to words

`convert_case` treats a digit as a word boundary by default, so `/api/v1/users` becomes `GetApiV_1Users` in pascal or `v_1` in snake case. Set the key to `false` to glue digits to the preceding word:

<Code lang="toml" code={`[naming]
preserve_numbers = false # v1 not v_1`} />

## Add prefixes, suffixes and extra separators

<Code lang="toml" code={`[naming]
variant_prefix  = "Api"    # ApiGetUsers
variant_suffix  = "Route"  # GetUsersRoute
word_separators = "+~"     # extra characters treated as word separators`} />

`/`, `-`, `.` and `:` always act as separators; `word_separators` adds further characters on top of that set.

## Resolve name collisions

Two routes can produce the same base name — for example `GET /users/deactivated` and a path parameter both mapping to `GetUsers`. Choose what the generator does:

<Code lang="toml" code={`[naming]
collision_strategy = "skip" # skip | append-method | number`} />

| Strategy | Behavior |
| :--- | :--- |
| `skip` (default) | Keep the first route, drop each duplicate, and emit a `cargo:warning` naming the skipped route. |
| `append-method` | Prefix the HTTP method to the duplicate: `GetUsers` versus `PostUsers`. |
| `number` | Append a counter to the duplicate: `Users`, `Users2`, `Users3`, ... |

<Aside type="caution">
  `skip` silently loses routes — the only trace is a build-time warning. Pick `append-method` or `number` when losing a route is unacceptable, or when your URLs differ only in a way the base name cannot express.
</Aside>

## Verify the result

Rebuild or re-run `route-info-builder generate`, then search the generated Rust file for your variants:

<Code lang="bash" code={`rg "pub enum Link" -A 12 src/links.rs`} />

<Aside type="note">
  `name()` on every variant returns the camelCase form of the same name the TypeScript client uses as its method key. Renaming variants therefore renames the client methods and the TanStack Query keys with them.
</Aside>
